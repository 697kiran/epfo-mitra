# EPFO Mitra

EPFO Mitra is an independent hackathon prototype that helps Indian citizens understand and recover from rejected EPF claims.

It turns a cryptic rejection into:

- A plain-language explanation.
- A deterministic diagnosis.
- A clear owner for each action: member, employer, or field office.
- A document and evidence checklist.
- Employer follow-up and grievance escalation guidance.
- A simulated path from rejection to claim submission.

> This is not an official EPFO or Government of India product. It does not contact EPFO, submit claims, file grievances, or process real credentials.

## The Problem

When an EPF claim is rejected, citizens often receive a short error code without enough context to understand:

- What actually caused the rejection.
- Whether they or their previous employer must act.
- Which document or form is needed.
- What to do when an employer does not respond.
- How to prepare for a cyber cafe, field office, or grievance filing.

EPFO Mitra focuses on that recovery moment rather than trying to recreate the entire government portal.

## Current Citizen Journey

1. Enter a mock UAN and password supplied separately for the demonstration.
2. Review a synthetic passbook dashboard with employers, dates, Member IDs, and balances.
3. Run a claim diagnosis or search an error pattern in plain language.
4. Read the deterministic status, root causes, statutory rule IDs, and recommended form.
5. Follow the Recovery Pack checklist and identify who must act.
6. Copy or print the evidence and escalation pack.
7. Use the HR email, Joint Declaration draft, or action slip generated by the app.
8. Simulate completion of member or employer actions.
9. Watch eligibility move from red or amber to green.
10. Complete the simulated ready-to-submit and confirmation screens.

## Features

### Deterministic EPFO rules engine

`src/lib/epfoRules.ts` contains the decision logic used by the app. It checks:

- Name mismatch between Aadhaar and the EPFO record.
- Date of Birth mismatch.
- Missing Date of Exit on previous employment.
- Unmerged or untransferred Member IDs.
- Service duration and TDS conditions.
- Form 19, Form 31, and Form 13 recommendations.
- Joint Declaration requirements.

The rules engine returns status, severity, root causes, rule IDs, action steps, service duration, TDS state, and recommended forms.

The `computeDiagnosis` function accepts an explicit `asOfDate`, so open-ended service calculations do not depend on the machine clock.

### Live remediation simulation

`applyRemediation` is a pure function that simulates an external action completing:

- `JOINT_DECLARATION_FILED` reconciles names and dates and resolves the Case 1 employer blocker.
- `ACCOUNTS_LINKED` consolidates synthetic accounts for Form 13 workflows.
- `FORM_15G_UPLOADED` simulates the member submitting the tax exemption route.

The UI shows an honest simulation label and a short “Re-checking eligibility” transition. It does not claim to have contacted an employer or EPFO.

### Four synthetic scenarios

- Case 1: Name mismatch and missing Date of Exit.
- Case 2: Service under five years and Form 15G/TDS issue.
- Case 3: Clean six-year advance claim ready to submit.
- Case 4: Three correctly exited employers requiring an ordered Form 13 transfer sequence.

All names, UANs, Member IDs, dates, and balances are synthetic demo data.

### Recovery Pack

`src/components/ClaimRecoveryPack.tsx` collects the practical material a citizen needs after a rejection:

- Rejection code and current recovery status.
- Dynamic evidence checklist based on the diagnosis.
- Aadhaar, PAN, passbook, Member ID, and employer-proof reminders where relevant.
- Employer follow-up tracking.
- Suggested seven-day escalation review.
- EPFiGMS grievance preparation guidance.
- Copy-to-clipboard recovery pack.
- Print recovery pack action.
- Recovery progress indicator.

### Citizen support tools

`src/components/CitizenSupportTools.tsx` provides:

- EPFiGMS grievance escalation guidance for an unresponsive employer.
- Searchable glossary for UAN, EPS, Form 13, Form 15G, Date of Exit, and KYC seeding.
- TDS comparison calculator showing estimated amount after 34.6% TDS versus the protected synthetic balance.
- Browser read-aloud using Speech Synthesis.
- WhatsApp-style chat presentation of the diagnosis.
- Mock nearest regional office lookup based on synthetic Member ID prefixes.
- English, Hindi, Tamil, Telugu, Bengali, and Marathi regional status summaries.
- Online/offline indicator for the demo shell.

These are guidance and demonstration tools only. They do not file a grievance, use live maps, or provide tax advice.

### Documents and citizen assistance

Existing supporting tools include:

- Joint Declaration draft.
- Employer HR request email.
- Clipboard copy actions.
- Printable cyber cafe action slip.
- Plain-language English and Hindi explanation templates.
- Optional LLM rewriting layer with deterministic offline fallback.
- Voice input with browser support, microphone permission, network, and no-speech error messages.

### Accessibility and navigation

- Mobile-first responsive layouts.
- Visible keyboard focus states.
- Reduced-motion support through `prefers-reduced-motion`.
- Large, readable status and action labels.
- Sticky journey navigation to Diagnosis, Recovery Pack, and More Help.
- Voice input fallback that remains visible when unsupported instead of silently disappearing.

### Offline-friendly PWA shell

The app includes:

- `public/manifest.webmanifest`.
- `public/sw.js` service worker.
- Cached app shell and manifest.
- Offline indicator for the simulated journey.
- Synthetic local data that can continue to support the demo without a government connection.

The offline layer is intentionally lightweight. It is not a complete production offline-sync system.

## Honesty and Safety Boundaries

This prototype deliberately does not:

- Contact a live EPFO portal.
- Use real Aadhaar, PAN, OTP, bank, payment, or biometric data.
- Authenticate against a real UAN account.
- Submit an EPFO claim.
- File an EPFiGMS grievance.
- Send an employer email.
- Use live maps or location tracking.
- Present itself as official or government-endorsed.

The mock login is only a client-side scenario selector. Demo credentials are supplied separately and are not displayed on the login screen.

The LLM layer, when configured, only rewrites an already-computed diagnosis into plain language. It is not allowed to determine claim eligibility or statutory outcomes. Without an API key, the app uses local templates.

## Local Setup

Requirements:

- Node.js 18 or later.
- npm.

Install and run:

```bash
cd epfo-mitra
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

Demo login credentials are intentionally distributed separately from the application front page.

## Optional LLM Configuration

The app works without an API key. To enable optional plain-language rewriting, create `.env.local`:

```env
LLM_API_KEY=your_key_here
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
```

Do not use real citizen data with this prototype.

## Suggested Two-Minute Demo

### Minute one: citizen journey

1. Log in with the separately provided demo credentials.
2. Show the synthetic passbook dashboard.
3. Open Case 1 and show the red diagnosis.
4. Scroll to the Recovery Pack and tick the evidence items.
5. Show the HR follow-up and EPFiGMS escalation guidance.
6. Click the simulated remediation action.
7. Show the status transition to green.
8. Submit the simulated claim and show the confirmation reference.

### Minute two: product explanation

Explain that EPFO Mitra is rules-engine first, uses synthetic data, creates an evidence-based recovery path, supports low-literacy and low-connectivity users, and clearly separates real logic from simulated integrations.

## Future Production Path

A real deployment would require official authorization and privacy review before any integration. A safe architecture would include:

- Explicit consent and data minimisation.
- Encrypted storage and transport.
- Versioned, reviewable rule definitions.
- Role-based employer workflows.
- Auditable action history.
- Verified EPFiGMS and regional-office directories.
- Clear tax and legal disclaimers.
- Human support for exceptional cases.

This prototype is intended to demonstrate the citizen experience and the recovery concept, not to imply government adoption or production connectivity.
